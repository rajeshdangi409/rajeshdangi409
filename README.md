<div align="center">

### Infrastructure Automation & End-to-End DevOps Pipeline on AWS

*A 5-repository, production-grade DevOps system — every layer built hands-on.*

╠══════════════╦═══════════════╦══════════════════╦═══════════════════════════╣

| Repository | Layer | What it does |
| :--- | :---: | :--- |
| [**cloudpulse-bootstrap**](https://github.com/rajeshdangi409/cloudpulse-bootstrap) | 🏗️ IaC | Modular Terraform — Bootstrap VPC, Jenkins + Ansible EC2, least-privilege IAM instance profile, S3 remote state + DynamoDB locking |
| [**cloudpulse-ansible**](https://github.com/rajeshdangi409/cloudpulse-ansible) | ⚙️ Config | 4-role Ansible playbook (java, docker, aws-tools, jenkins) — fully idempotent, event-driven handlers, Trivy + Flux CLI installed |
| [**cloudpulse-infra**](https://github.com/rajeshdangi409/cloudpulse-infra) | ☁️ Infra | Production VPC, private-subnet EKS cluster (zero public IPs), ECR registry, FluxCD bootstrap — via Jenkins pipeline with approval gate |
| [**cloudpulse-app**](https://github.com/rajeshdangi409/cloudpulse-app) | 🐍 App + CI | Python Flask app + Jenkins CI: webhook → flake8 → pytest → Docker build → ECR push → image tag commit |
| [**cloudpulse-config**](https://github.com/rajeshdangi409/cloudpulse-config) | 🔄 GitOps | K8s manifests (Deployment, Service, Namespace, Kustomization) watched by FluxCD — pull-based CD, CI and CD fully decoupled |

<br/>

<details>
<summary><b>⚡ Key Engineering Decisions (click to expand)</b></summary>

<br/>

**🔐 No static AWS keys anywhere**
Jenkins EC2 authenticates to AWS via an IAM instance profile — credentials are never stored as environment variables or files.

**🔒 Private EKS worker nodes**
All EKS node groups run in private subnets with zero public IP assignment. External traffic routes through NAT Gateway only.

**🔄 CI and CD are fully decoupled**
Jenkins handles build and push. FluxCD handles deploy. They communicate only via a git commit to the config repo — this is true GitOps. It also prevents webhook loops between the app repo and config repo.

**✅ Idempotent Ansible roles**
Every role includes a verification step that checks if the tool is already installed and at the correct version before attempting install. Handlers only fire on actual config change.

**🛡️ Image vulnerability scanning**
Trivy is installed via the `aws-tools` Ansible role and runs as part of the pipeline to scan Docker images before pushing to ECR.

</details>
